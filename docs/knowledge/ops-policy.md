# Gaia / aiflow 知识库运营制度（一页纸）

> 版本：V1.0 · 2026-10-22  
> 适用：Gaia（`gaia.yafex.cn` 私有化 Dify）现行运营；aiflow 自建知识层时沿用同一职责边界。  
> 原则：**业务对内容负责，产品对结构负责，测试对召回质量负责，开发对平台管道负责。**

---

## 1. 目标

把「知识库」当成可运营的产品，而不是开发附带活：

- 内容可更新、可下线、可追责  
- 应用绑定清晰，禁止串库  
- 每次大变更有召回回归  
- 使用人（产品 / 测试 / 业务）能进库自助，不依赖开发传文档  

---

## 2. 角色与职责（RACI 摘要）

| 角色 | 负责什么 | 不负责什么 |
|------|----------|------------|
| **业务 Owner**（人事行政 / IT / 刊登运营等） | 上传替换文档、启用/禁用、过期下线、内容对错 | Embedding、TopK、向量库故障 |
| **产品经理**（知识产品负责人，可兼职） | 库边界、应用绑定规则、验收标准、标签体系 | 日常当文档搬运工（冷启动可短期帮忙） |
| **测试** | 金标题集、召回回归、缺陷单（问句/期望/实际） | 改制度原文、改模型通道 |
| **开发 / 平台** | 权限、配额、模型通道、同步管道、监控、默认检索模板落地 | 日常维护考勤制度 / 分类表 Word |

图例约定：内容变更 **业务拍板**；结构变更 **产品拍板**；管道故障 **开发拍板**。

---

## 3. 知识产品分层（默认空间建议）

| 知识产品 | 收录范围 | 服务应用 | Owner |
|----------|----------|----------|-------|
| 平台分类本体 | 美客多 / TikTok / eBay / Amazon 分类资料 | 分类匹配类 Workflow | 刊登 / 平台运营 |
| 人事行政制度 | HR/AD 制度 + 行政 QA | 人事行政数字客服 | 行政 / HR |
| 业务系统手册 | OMS/WMS/OA/APS/刊登 FAQ（合并重复库） | IT 数字客服 | IT |
| 实验沙箱 | 草稿、测试、空壳 | 禁止绑生产应用 | AI 平台组 |

硬规则：

1. **一个生产应用只绑一个权威库**（或明确的主库 + 只读辅库清单，需产品批准）。  
2. **探索/沙箱内容永不进生产 Bot**。  
3. **禁止跨平台串绑**（例：美客多分类库不得绑 TikTok 应用）。  

---

## 4. 标准发布流程

```
业务改文档 → 知识库内发布/启用
    → 测试跑该库金标题集
    → 产品确认可上线
    → 应用继续使用
```

出问题排查顺序（先业务侧，后开发侧）：

1. 文档是否启用？是否过期未下线？  
2. 应用是否绑错库？  
3. 题集是否覆盖该问法？  
4. 再查平台：索引失败、模型通道、配额、权限。  

---

## 5. 权限最低要求

| 人群 | 默认空间至少具备 |
|------|------------------|
| 业务 Owner / 产品 / 测试 | 可见「知识库」菜单；可编辑自己负责的库 |
| 普通业务使用者 | 可用工作室应用即可（可不给改库权） |
| 开发 / 平台管理员 | 全库与系统配置；退出日常传文档 |

现状提醒（2026-10-22 调研）：普通成员在「默认空间」可能看不到知识库入口——**须向 Gaia 管理员申请**，否则本制度无法执行。

---

## 6. 质量底线（每月至少看一次）

- 生产库文档不得长期全量 `disabled`  
- 每库维护 **30～50 条** 金标问答；大更新后回归  
- 指标建议：无命中率、低分命中率、Top 未命中 Query、文档更新后重索引延迟  
- 空壳库（0 文档）须补齐或归档，不得挂生产应用  

---

## 7. 与 aiflow 的边界

| 层 | 系统 | 谁维护 |
|----|------|--------|
| 知识运营界面、分段索引、召回测试 | Gaia（现阶段） | 业务 / 产品 / 测试 |
| Agent / 工作流 / 权限 / 积分 | aiflow | 开发 |
| 检索调用 | aiflow Tool → Gaia API（或后续自建） | 开发维护连接；业务仍维护内容 |

学架子 = 学职责边界 + 生命周期；不是让开发再写一个「只给自己传 PDF」的后台。
